# /ingest — vault 全体のリンク付け

対象 vault: `$ARGUMENTS`（空ならカレントディレクトリ）。以下 `<vault>` と書く。
ヘルパー: `${CLAUDE_SKILL_DIR}/scripts/link_mentions.py`（Python 3 標準ライブラリのみ）。

## 決まっていること（ユーザー確認済み）

- 変更は**確認なしで自動反映**し、最後に変更一覧を報告する
- 本文中の言及は**すべての出現**をリンク化する
- 新規ノートは `<vault>/概念/` に作る
- **vault 全体が対象**。vault 内の複数の wiki（Labo-wiki・pharmacy-wiki など）をまたいでリンクしてよい
- **`raw/` フォルダ内のノートは書き換えない**（元資料）。リンク先としては使う（他のノートから raw のノートへのリンクは張る）。関連ノートの追記も新規ノートからの言及も、raw 内のファイルには一切書き込まない
- `CLAUDE.md` / `AGENTS.md` は対象外（リンク先にも書き換え対象にもしない）
- 除外フォルダは `.obsidian` `.trash` `.git` `.claude` `.ingest-backup`。それ以外の .md はすべて対象
- **2文字以下の名前**（例: AI, UX）はまとめてユーザーに確認してから適用する
- わからないこと・判断に迷うことは、推測で進めず**その都度ユーザーに聞く**（AskUserQuestion を使い、迷う点はなるべく1回にまとめて聞く）

## 手順

### 0. 準備
1. `<vault>` に `.obsidian/` があるか確認。なければ Obsidian の vault で合っているか聞く。
2. `<vault>` が git 管理なら `git status` を見て、未コミットの変更があれば先にコミットするか聞く。git 管理でなければ、スクリプトが `.ingest-backup/<日時>/` に変更前のファイルを保存することを伝えて進める。
3. 一覧を取得:
   `python3 "${CLAUDE_SKILL_DIR}/scripts/link_mentions.py" <vault> --inventory`
   - `duplicate_names`（同名ノートが複数。wiki ごとの `_index` など）や `ambiguous_aliases`（同じエイリアスが複数ノートにある）があれば、どれにリンクすべきかユーザーに聞く。回答に応じてノートの `aliases` を整理するか、その名前はスキップする。

### 1. 新規ノートの作成（`概念/`）
1. 全ノートを読み、**2つ以上のノートに登場する**が、対応するノート（名前・エイリアス）がない重要な概念・手法・人物・用語を洗い出す。一般的すぎる語（「研究」「方法」など）は除く。
2. 候補が多すぎる（目安 20 件超）・境界があいまいな候補があるときは、一覧を見せて作るものを選んでもらう。それ以外は確認なしで作る。
3. 各ノートを `<vault>/概念/<概念名>.md` に作る:
   ```markdown
   ---
   aliases: [表記ゆれ・略語があれば]
   tags: [ingest-generated]
   created: YYYY-MM-DD
   ---
   # <概念名>

   <vault 内の記述だけを根拠にした 1〜3 文の説明。vault にない情報は書かない。>

   ## 登場するノート
   - [[ノートA]] — どういう文脈で出てくるか
   - [[ノートB]] — …
   ```
4. 表記ゆれ（例: 「有害事象」と「副作用」）を同じ概念として扱うか迷ったら聞く。

### 2. 言及のリンク化（スクリプト）
1. まず `--dry-run` で件数を確認:
   `python3 "${CLAUDE_SKILL_DIR}/scripts/link_mentions.py" <vault> --dry-run`
2. `short_terms_pending`（2文字以下の語と出現数）があれば、実際の文脈を数例ずつ grep で示して、どれをリンク化するかユーザーに聞く（multiSelect）。
3. 本番実行（承認された短い語を渡す）:
   `python3 "${CLAUDE_SKILL_DIR}/scripts/link_mentions.py" <vault> --approve-short AI,UX`

スクリプトの挙動:
- ノート名・frontmatter の `aliases` を長い順に一致させる。エイリアス一致は `[[ノート名|表記]]` になる
- 英字は大文字小文字を区別しない。英数字の語は単語境界のみ一致（`AI` は `MAIL` に一致しない）
- frontmatter・見出し行・コードブロック・インラインコード・数式・既存リンク・URL・タグ・HTML はリンク化しない
- 自分自身へのリンクは張らない。何度実行しても同じ結果になる（冪等）

### 3. 「関連ノート」セクションの追加
1. `raw/` 以外の各ノートについて、内容が近いのに**まだリンクでつながっていない**ノートを最大 5 件選ぶ（共通の概念・同じ論文/手法/テーマを扱っている、など。根拠が弱いものは入れない）。
2. ノート末尾に以下のブロックを追加する。すでにブロックがあれば**マーカー間だけ**置き換える（マーカー外の手書き部分は触らない）:
   ```markdown
   ## 関連ノート
   <!-- ingest:related:start -->
   - [[ノートX]] — 関連の理由を一言
   <!-- ingest:related:end -->
   ```
3. 関連が見つからないノートにはブロックを追加しない。
4. ノートが多い（目安 200 超）ときは、フォルダ単位で進めて途中経過を報告する。

### 4. 仕上げと報告
1. 手順 2 のスクリプトをもう一度実行し（`概念/` の新規ノートへの言及もリンク化される）、`links_added` が 0 になるまで確認する。
2. 最後に日本語で報告する:
   - 新規作成したノート（`概念/` 内の一覧）
   - リンクを追加したファイル数・リンク数（上位ファイル）
   - 関連ノートを追加したノート数
   - スキップしたもの（同名ノート・曖昧なエイリアス・未承認の短い語）とその理由
   - バックアップの場所（`.ingest-backup/...`）または git の差分の見方

## してはいけないこと
- `.obsidian/` 内の設定ファイルを編集しない
- ノートの本文の意味を変える書き換え・削除をしない（追加するのはリンク記法と「関連ノート」ブロック、新規ノートのみ）
- ファイル名の変更・移動をしない（必要だと思ったら提案だけする）
- vault に書かれていない事実を新規ノートに書かない
